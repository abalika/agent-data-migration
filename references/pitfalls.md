# 陷阱库（23 条，全部来自真实事故）

按"症状 → 根因 → 处置"排列。出问题时先在这里搜症状。

| # | 症状 | 根因 | 处置 |
| --- | --- | --- | --- |
| 1 | 迁移后会话列表全空 | 会话文件被整文件重压成单帧，而应用要求"第 1 帧恰好是头部一行" | 重新分帧：头一帧，其余按行边界切块；写入前内存校验 |
| 2 | 点开某会话是空白 | 工作区登记了已删除的会话，文件不存在 | 从登记里移除失效 id（先备份 JSON） |
| 3 | 插件加载失败 / 插件消失 | pnpm `file:` 依赖是指向源码的符号链接，搬目录即断 | 重建链接，**含 `node_modules/@scope/` 层** |
| 4 | 双击 `.cmd` 报"不是内部或外部命令"，出现奇怪的碎片错误 | `.cmd` 里写了非 ASCII + LF 换行，cmd.exe 按字节错位断行 | 改纯 ASCII + 单行；中文交给 PowerShell 输出 |
| 5 | venv 里 `pip` 报 Fatal error 或无输出、exit 1 | 启动器内嵌旧 shebang | 用 distlib 重建（`regen_launchers.py`） |
| 6 | 应用启动后读的还是旧数据 | 只改了启动脚本，没改**用户级环境变量** | 两处都改，改完新开进程验证 |
| 7 | 移动后应用报 "directory does not exist" | 数据库/会话里存的是绝对 cwd | 改库 + 改会话头 + 改 slug 目录名 |
| 8 | 空目录删了又自动出现 | 应用会重建它 | 记为已知项，不要反复删 |
| 9 | 计划任务还在用旧路径 | 迁移时漏了 L7 | `Set-ScheduledTask` 逐条改 |
| 10 | 迁移前后数量对不上（40 vs 41） | 基线漂移：当前会话自己新建了目录 | 用 `>=` 判据，或用前排除当前会话目录 |
| 11 | 数据库备份"少了几百行" | WAL 里的提交还没 checkpoint 进主文件 | 用 `VACUUM INTO` 或 `.backup`，产物必须 `integrity_check` |
| 12 | `WinError 1224` 复制失败 | 连接打开时复制 `-wal`/`-shm` | 停应用，或走 backup API |
| 13 | 字符串比对莫名失败 | heredoc 把 `\\` 转成了 `//` | 涉及反斜杠的脚本写成 `.py` 文件再跑 |
| 14 | 读 `.lnk` 被安全策略拒绝 | COM `WScript.Shell` 被拦 | 改走 ShellLink 结构纯字节解析，或让用户手动改 |
| 15 | 文本替换误伤验收记录 | 替换边界太宽（含中文标点） | 严格区分操作性引用与历史记录 |
| 16 | `LIKE '%关键字%'` 查不到 | 库里路径以正斜杠存储 | 用 `LIKE`，不要用带反斜杠的前缀匹配 |
| 17 | junction 被判成普通目录 | `os.path.islink()` 认不出 junction | 用 `lstat().st_file_attributes & 0x400` |
| 18 | 悬空联接删不掉 | 目标已移走，路径解析失败 | `Directory.Delete($p,$false)` 或 `RemoveDirectoryW` |
| 19 | 命令被沙箱/审批拦下 | 是安全策略，不是 bug | 换合规路径，不要绕过 |
| 20 | 应用重启后列表为空 | 内部索引/缓存被换成"结构对了但内容不对"的版本 | 缓存只改路径，不改结构 |
| 21 | 迁完发现权限变了 | 跨盘 `/COPY:DAT` 不保 ACL，目标继承父目录 | 迁移前后 `Get-Acl` 对比，必要时重建 ACE |
| 22 | robocopy 卡住几小时不动 | `/R` 默认 100 万次、`/W` 默认 30 秒 | 显式 `/R:2 /W:2`，并加 `/LOG` |
| 23 | 不知道谁占着文件 | 没查占用就猜 | `who-locks.ps1`（Restart Manager） |

## 三条通用排障原则

1. **按上游到下游查**：应用日志 → 应用读取代码 → 数据文件 → 目录路径 → 应用状态。不要从"猜文件坏了"开始。
2. **看应用怎么读，而不是文件能不能打开**：文件"能解压、能读出内容"不等于"应用能读"。
   必要时把应用的校验逻辑从源码里抄出来复刻一遍。
3. **先证伪再动手**：怀疑某个文件时，先拿一个"没被改过的同类文件"做对照，看差异在哪。

## 恢复顺序

一旦确认迁坏了：

1. 停应用
2. 用 `journal.json` 回滚（`apply.py --rollback`）
3. 还原配置备份（`maintenance/<批次>/backup/configs`）
4. 还原数据库快照
5. 还原环境变量
6. 重启应用，打开一条历史验证

回滚之后再排查具体哪一步出错，不要在坏状态上继续修。
